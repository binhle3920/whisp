# Gmail input

Gmail is the first Whisp input provider. It uses the Gmail API with read-only access to
detect new messages and convert their MIME payloads into Whisp's common email model. It
cannot send, delete, label, or otherwise modify email.

## What you need

- A Google account with Gmail
- A Google Cloud project
- An OAuth client configured as a desktop application

Google's official setup entry point is the
[Gmail API quickstart](https://developers.google.com/workspace/gmail/api/quickstart/python).

## Enable the Gmail API

1. Open the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a project or select an existing one.
3. Open **APIs & Services → Library**.
4. Find **Gmail API** and select **Enable**.

## Configure OAuth consent

Open **Google Auth Platform** for the project and configure the application:

1. Set the application name to `Whisp`.
2. Choose an external audience for a personal Gmail account.
3. Keep the application in testing while Whisp is for your own use.
4. Add your Gmail address as a test user.
5. Add the `https://www.googleapis.com/auth/gmail.readonly` scope when the console asks
   for data access.

Google changes the names and grouping of OAuth screens occasionally. The required outcome
is an external application where your Gmail address is allowed to authorize Whisp. For
continuous use, publishing the OAuth app avoids testing-mode refresh tokens expiring after
seven days.

## Create the OAuth client

1. Open the project's **Clients** or **Credentials** page.
2. Select **Create client** or **Create credentials → OAuth client ID**.
3. Choose **Desktop app** as the application type.
4. Name the client `Whisp local`.
5. Download the client JSON file.
6. Save it as `credentials/google_credentials.json` in the Whisp repository.

The file is ignored by Git and must never be committed.

## Configure file locations

Whisp keeps all file-based credentials in one directory. The default `.env` value is:

```env
WHISP_CREDENTIALS_DIR=./credentials
```

The Gmail input uses these fixed names inside that directory:

- `google_credentials.json` — the OAuth desktop client downloaded from Google
- `google_token.json` — the renewable user token generated by Whisp

Change `WHISP_CREDENTIALS_DIR` if all credential files should live elsewhere.

## Authorize Whisp

Run the authorization command from the repository root:

```bash
uv run whisp authorize
```

Whisp opens Google in your browser. Sign in with the allowed Gmail account, review the
read-only permission, and approve access. Whisp then writes the renewable OAuth token to
`credentials/google_token.json`.

You should see:

```text
Gmail authorization saved to credentials/google_token.json
```

Keep the entire `credentials/` directory private. Anyone with the refresh token and OAuth
client credentials may be able to read the authorized mailbox.

## Verify the input

After configuring the processor and output, run:

```bash
uv run whisp poll --backfill
```

The result should report one or more discovered messages if the inbox contains recent
mail. Whisp stores the Gmail history cursor in its local SQLite database.

## Troubleshooting

### Access blocked or access denied

Confirm that the Google OAuth application allows the Gmail account you selected.

### Redirect URI or browser callback error

Confirm that the downloaded client is a **Desktop app** client. A web application client
uses a different callback configuration and will not work with local authorization.

### Token expired or revoked

Remove `credentials/google_token.json` and run `uv run whisp authorize` again. Revoking
Whisp from your Google Account security settings also invalidates the local token.

### Gmail history cursor expired

Gmail history cursors eventually expire. Whisp records the current mailbox position and
resumes with new messages. Mail received during the missing window is not backfilled
automatically.
